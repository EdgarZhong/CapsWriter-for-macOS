# ASR 评测目录约定

本目录用于后续沉淀 Qwen3-ASR MLX 路线的精度、性能与回归评测材料。

当前阶段只搭地基：整理目录边界，不下载数据集，不实现完整评测驱动，不写复杂指标逻辑。

## 目录结构

```text
evals/
  datasets/       数据集清单、manifest、少量元信息；不直接提交大体积音频数据
  drivers/        评测驱动代码入口；后续负责调用不同后端、收集输出与指标
  results/        本地评测结果输出；默认作为临时结果区，精选报告再决定是否提交
  manual_cases/   少量手工录入或手动录制的回归样例，用于快速复查具体问题
  README.md       本文件，维护评测目录约定
```

## 数据集约定

- `datasets/` 优先存放 manifest 或下载说明，不直接纳入大型公开数据集原始文件。
- manifest 后续统一描述音频路径、参考文本、语言、场景、时长、来源与许可证口径。
- 真实数据集下载、筛选与许可证核对后续单独推进，本轮不处理。

## 当前评测集口径

- 初期 Golden Set 优先覆盖中英文技术口述，不追求泛化到所有语言或所有生活场景。
- 初期不要求用户自录数据集；优先使用公开数据集、可复现筛选、可复现声学增强和必要的公开 TTS/合成样本。
- 低语和小声说话是核心评测条件，不能只作为少量噪声增强样本处理。
- 中文低语、英文低语、中英混合低语都需要单独覆盖，因为便携电脑端用户经常在办公室、会议室、公共空间中压低音量输入。
- manifest 中需要区分真实低语、低音量正常发声、后期降增益三类条件，避免把“音量变小”和“低语发声方式变化”混为一谈。
- 每轮快速评测应保留较高比例的低语/小声样本，防止调优只改善清晰朗读而牺牲真实使用场景。
- 评测设计按两个正交维度组织：
  - 内容场景维度：中文技术讲解、英文技术词汇、商业/技术会议、命令式口述、中英混合术语。
  - 声学条件维度：正常音量、小声说话、真实低语、低增益增强、噪声/混响/远场。
- 公开数据集很难天然同时覆盖“真实低语 + 技术内容”，因此 manifest 需要保留来源和条件标签，允许用不同数据集分别覆盖内容场景与声学条件，再用固定抽样和增强形成稳定评测矩阵。
- 当前阶段不改产品预处理链路，不新增响度归一化、AGC 或降噪；评测目标是在现有录音、重采样、log-mel 管线下观察模型与接入策略的真实表现。

## 驱动代码约定

- `drivers/` 只放评测入口和薄封装，避免把模型适配逻辑复制到评测目录。
- 评测驱动后续应复用主项目已有后端或 `mlx-qwen3-asr` 子仓库能力。
- 初期优先支持单条样例和小批量 manifest，等口径稳定后再扩展批量报告。

## 结果约定

- `results/` 用于本地输出识别结果、耗时、指标和中间日志。
- 大体积或机器相关结果默认不提交；需要长期留存的报告再整理成小文件提交。

## 手工样例约定

- `manual_cases/` 用于少量人工构造的回归样例，覆盖热词、专名、中英混输、短句口述等场景。
- 手工样例数量保持少而精，目标是快速定位回归，不替代正式数据集评测。
- 未带 `annotation_version` 的旧根目录 `manual_cases/cases.jsonl` 统一视为 v1；其形成于旧口径，可信度较低，只读保留，不迁移、不改写。
- 2026-08-24 起的新口径为 v2：记录只写入 `manual_cases/v2/cases.jsonl`，音频只写入 `manual_cases/v2/audio/`，且每条记录固定带 `annotation_version: 2`；v1 与 v2 必须物理隔离。
- 后续评测默认只读取 v2；只有明确进行兼容性分析时才读取 v1。评测文档、日志和提交内容不得写入或展示个人语料文本及音频内容。
