## 用户确认的目标

顶栏与系统标题栏同一层厚度，视觉高度 52pt。上方主体持续保持最强模糊，底部约 24pt 快速过渡到无模糊；滚动内容进入顶栏时逐渐柔化。红绿灯、标题和右上角三档外观开关保持清晰且可操作。不得出现色带、白块、黑块，不得把模糊扩散覆盖到下方主体区域。

底层继续使用已确认的透明窗口、根层整窗 `.behindWindow` 背板和透明容器背景；背板业务名为 `DashboardSurfaceStyle.backdropMaterial`，底层系统枚举仍映射到 `.sidebar`，本轮不更换其观感。侧栏更透是后续独立事项。

## 已确认事实与未证实假设

已确认：

- `makeNSView`、`updateNSView`、`viewDidMoveToWindow` 均执行；之前没有日志不是“代表视图未进入层级”的证据。
- 当前运行树中的滤镜虽挂在 `NSSplitView` 下，但不属于 arranged panes。不能仅凭 superview 类型就断言它参与了 pane 布局或必须迁出。
- 顶栏可见几何是 52pt，遮罩意图是在内部 24pt 内从无模糊过渡到最大值；当前最大半径是 30pt。
- 36pt 异常是一次观察，不是已定位的 Core Image 上限；Apple API 并未给出 30/36 这样的特殊阈值。
- 代码缓存只比较滤镜 view 的 `size`，而遮罩使用窗口坐标；当窗口内 view 原点改变但尺寸不变时，遮罩可能过期。这是明确的代码风险，尚未证明它就是白块/透明现象的根因。

仍待验证：

- 24pt 过渡在当前系统合成下是否足够明显，以及更高最大半径是否会改善观感。
- 增加全黑 clear tail 能否避免较大模糊半径下的边缘采样问题。`max(48, radius * 2)` 是外部研究提出的工程假设，不是已确认的 Apple API 要求；当前没有实现。
- Sidebar 折叠、分隔线拖动、窗口缩放时，滤镜窗口坐标和可见效果是否始终同步。
- 浅色、深色、减少透明度及长列表滚动的完整逐项验收仍未完成。

## 恢复排查时的建议顺序

1. 先从本文件和 `docs/dashboard-窗口材质分层规格.md` 恢复目标与已知事实，并比较当前源码、30pt 暂存版本和 22:42 旧构建。
2. 保持 52pt 和 24pt 不变，先修正遮罩缓存，使窗口坐标矩形、最大半径和过渡高度变化时都能更新；验证侧栏收放、分隔线和 resize。
3. 若要试 clear tail，单独加入黑色 0 blur 区并保持 30pt，先判断是否引入可见模糊或色块；不要把 tail 误记成视觉高度。
4. 结构稳定后再单变量调整最大半径。每档记录浅色/深色、滚动位置、窗口几何及截图；异常时保留证据，不宣称某个数值是阈值。
5. 按材质规格第五节逐项验收；只有全部通过后，才把顶栏与侧栏材质层级标为完成。
